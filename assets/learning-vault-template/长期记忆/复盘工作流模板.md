# 复盘工作流与日常提示

本文件负责复盘任务，不承载另一套题源或学情规则。证据与状态见学习判断与证据规范，执行与版本见执行与验收规范。

## 日常短指令

- “先分类归档，周末再做。” → 日常使用 `triage`；完成视觉识别、必要的轻量 OCR/预索引、分拣、日志和待确认，周末用 `weekly` 继续深度处理。
- “放好了，按学了么处理这批资料。” → 扫描、分拣并完成实际对应学习流程；不自动扩成周报。
- “本周资料齐了，出周复盘和学生打印版。” → 按实际截止日、三线资料和当前看板完成四件套。
- “回做结果放好了，检查是否独立通过，更新重点。” → 按 `homework` 登记 `followup=true`，核对回传、交付孩子反馈，并关联原周计划与独立作答事件，更新作业/知识点追踪、复盘日志和看板；不自动重出整套周报。
- “只处理物理这份测验。” → 限定范围完成试卷流程。
- “继续上次没做完的任务。” → 读取任务记录并运行status，从未完成项继续。
- “这份结果有问题，检查原因并修正。” → 回原材料，区分个案错误与规则问题，保留修订依据。
- “做本月复盘，按月度复盘流程深度处理统计期内全部资料，包含最后一周；给孩子月度复盘册、验证练习和独立答案，不要家长版。” → 启动 `review`，按截止日纳入全部资料；仅做过 `triage` 的资料在本批补做深度处理，前序深度产物复用后回原材料复核。

默认指令无需家长重复粘贴长规范；实际使用规则版本、范围、必交付项由工作区入口和运行记录明确。

## 周复盘

先回看上期目标和回传 → 核本周实际资料、分拣/深度处理记录 → 列知识点全集 → 选少量可验证目标 → 核题源、进度和完整用时 → 生成并审核家长版与学生/答案件 → 发布 → 接收独立作答 → 下次决定减量、继续或换方法。

### 上期接续

- 从最近一次相关周报、任务记录和当前看板提取实际布置的重点，逐项记录：独立通过、提示后通过、仍卡住、未做、未收到结果；附回传位置和本次取舍。一次独立通过可减掉本次同题重复量，长期掌握状态仍按证据规范判断。
- 没回传只能说明效果待验证，不能写成再次错误，也不能把上期所有任务原样叠加。首周或没有相关历史计划，说明已查范围，以本次目标建立基线；不要求补做历史周报。
- 新资料可能已包含相关独立作答，先查现有作业/测验再请家长补充。家长不负责判断错因，只需提供原始结果与是否看答案/有提示；耗时知道就记录，不知道不推算。

### 本周选什么、做多久

- 默认选1–3个可观察的目标，合并能用同一小任务验证的目标。学科数和用时按本次要求，其次当前看板；数量是减负建议，不为凑数制造问题。六科资料覆盖完整，孩子只执行本次必做。
- 每项目标写具体材料依据、学生文件/页码/题号、通过标准、卡住或时间到的停止条件、下一次验证时机，并至少关联一道与本周弱项匹配、逐题核验过的北京高考原题或完整节选。卡片、校内旧题和题源限制不能替代重点真题。没有明确重点时，整份周打印版也至少保留一道按本周知识点或历史待验证弱项选出的北京高考原题或完整节选。通常先独立试一小段，再补最小必要讲解和回做，保留“提示后通过”的区别。
- `time_budget_minutes` 覆盖本次安排的全部必做：阅读、卡片、口述、做题、核对、订正及本周末复测。题目与非题目活动分别登记，不能题目已占满上限又附加卡片/周日复做；也不能把同一任务计两次。时间到就按停止条件结束。
- 下周自然出现的学校作业可作保持/迁移证据，无须另加家庭题。另布置的复测须在所属任务的预算内；未核验的新题不得先写成确定作业。
- 非重点科目没有可靠题源、孩子已有足够任务或证据不足时，可减少或不安排必做并说明原因。重点科目找不到适配北京高考原题时，不能用卡片代替后发布正式周打印版；应继续核题、缩小重点或明确报告阻塞。选做明确为剩余时间内自选，不暗示必须补完。

### 周报交付与验收

家长版开头先给简短决策摘要：上期哪些已通过/仍待验证，本周先做哪几个目标、合计多少时间、停在哪里，以及做完回传什么。每项目标的依据与详细六科记录接在后面；不让家长从六科长文中自行拼任务。

以上内容写进现有 `parent_md`、`overview_md` 和 `run.json.weekly_plan`，不另增家长表格。字段和固定验收见技能 `references/run-contract.md`。学习审核须对照正文、题目/活动清单与时间合计，检查所有必做都可定位、目标有证据、没有隐含加量；程序不替代这一步实际内容检查。

“周报已交付”与“学习效果已验证”分开记录。判断有效看孩子能否独立解释/作答、下次同类问题能否保持、因此减少了哪些重复训练；没有回传不声称提分或掌握改善。连续未通过时先查前次执行与提示条件，再调整方法。

### 作答后的反馈闭环

周打印阶段不生成“做完后核对”。家长回传本周学生版后，另开 `homework + followup=true`：核对实际作答 → 判定独立/提示/看过答案 → 交付孩子能读懂的“做完后核对”反馈 → 给最小修正动作 → 下次独立验证 → 按证据更新重点和减量。系统记录更新与孩子反馈均须验收。

回做检查每个有效学科必须有反馈。全部做对也给简短结果、独立性说明与减量建议。没有本周学生版回传就不生成反馈、不预测结果；上期结果只用于本周选题与减量。已按同样标准交付的反馈可复用核验后的正文，逐项关联本批依据，无须让孩子重复做题。

字段、答案隔离和排版统一见学生打印版规范。反馈本身不是新测验；订正和看过答案后的正确不能直接用来升级掌握。反馈要求与后续任务同时计入原有预算，不因增加文件而增加训练量。

### 日常到周末的交接

平时 `triage` 的候选主题只作检索入口。周末先读本周处理日志及相关运行状态，复用已完成的可靠产物，回原图核关键判断；只分拣过的继续深度处理。新到/遗漏资料说明是否属于本批，缺材料学科如实列出；不等六科凑齐才开始，也不把旧材料冒充本周新表现。

## 同类问题再次出现

先分清“孩子同一知识点再次错”与“助手再次交付失误”：

- 孩子再次错：确认独立事件、作答条件和前次干预；调整练法与验证，不自动改工作区规则。
- 助手重复失误：核是否规则漏读、版本不一致、规则冲突、证据不足或验收缺项；记录具体失败案例，修复可复用原因。
- 单次特殊情况：留对应日志；不要把每个例外变成所有任务永久负担。

## 月度/学期复盘

先读当前看板和期间证据，再对统计期间的全部资料做深度复盘，必要时回原资料。月度/学期复盘的正式学生交付为：表格化学生月度复盘册、学生验证练习、独立答案和长期记忆更新；不要求家长版。复盘册要完整回答：这段时间学了/接触了什么、哪些已有表现或改善、哪些仍薄弱、哪些只是待验证、典型错点是什么、下阶段如何验证。至少建立覆盖每个有材料学科的知识点表，列出事实证据、当前状态、做对或改善处、典型错点、证据位置和下一次验证。截止日前最后一周的资料也必须纳入深度复盘；此前若只有 `triage` 分拣预索引，本次要继续完成内容核对、知识点归纳、作答与批注核对以及证据判断，不能只引用分拣日志。已在前序流程深度处理的资料可复用，但要回原材料核对关键判断并记录复核。除确实无法可靠读取或缺核心材料的阻塞项外，不得把期间资料暂缓/排除；阻塞项须写具体原因、下一步和交付限制。

验证题按证据和知识结构选取，不按“每科一道题”凑数：狭窄知识点可以用多道小题，多个模型联动可以用综合大题；已经有稳定独立表现的内容可只安排保持/迁移观察，证据不足的内容不强行下结论。每道题必须关联具体目标，回到核验过的原题或完整节选，学生件保留题干、原文/材料、图表、选项、条件和小问；名著、文学阅读和材料题不能只保留题意概括。

月度/学期复盘不设固定总用时上限。题目可以写建议用时、建议分段和停止条件，实际训练时间根据覆盖完整性、孩子当月负担和题目难度决定；复盘册阅读时间与做题时间分开记录。不能为了满足某个预设分钟数删除必要的知识点覆盖，也不因为内容较多而把所有题都强制列为必做。

输出仍需说明：改善了什么、什么仍反复、证据不足在哪里、下一阶段少量优先目标和每道验证题的建议用时。学校日程和未来课程未经确认，标为待确认，不写成硬任务。

仅请求复盘时，可更新既有授权范围内的学情状态；长期规划/规则大改先给具体建议，已有明确升级授权则直接落实。权限根据任务授权，不根据模型名称。

## 规则更新

现行规则改在唯一权威文件，规则变更记录仅留日期、原因、影响和验证结果。旧规则标历史/失效，不通过在不同文件尾部不断补丁形成冲突。维护测试与孩子学习日志分开。

没有用户要求不新建自动化、不定时扫描；用户已明确要求的自动化按其范围执行。
