# 学了么执行与验收规范

生效：2026-09-19；执行规范 1.5，配套技能 0.5.1。旧资料保留，新增处理使用本规范。

| 追踪表、复盘日志、规则变更记录、历史版本 | 历史证据与变更说明；不新增或覆盖现行指令 |

用户本次及此前仍适用的明确指令优先于工作区默认规范；上级系统约束照常适用。规则冲突按职责归属解决，不简单以“文件更长/模型更高级/日期更晚”判断。发现影响正确性或孩子负担的未解决冲突，先处理确定部分，列出冲突及建议，不擅自拼成新规则。

“必须”用于原始证据、题源准确、隐私、答案隔离、完整交付等要求；数量/形式建议为默认，可依据已有任务授权和证据调整并记录原因。不能降低正确性或隐藏漏项来满足数量。

## 启动

先读双索引，再读本文件、证据规范和本任务专项规范。用已安装的 `$xuelema`，检查安装与维护源一致。不要靠技能名称、旧对话或模型名称猜规则已经加载。

普通讨论、查询、单条学习解释不强制建立批次或生成文件；用户请求整理资料、诊断、周复盘、练习或打印时，登记对应流程。系统维护用隔离测试，不改写孩子历史成绩或把维护动作写成学习进步。

任务范围至少明确：用户目标、学科、输入目录/文件、实际截止日、所需索引；周复盘另明确自然周目录与孩子本次用时。日常只分类归档时登记 `triage`，完成表示视觉识别、必要的轻量 OCR/预索引、分拣阶段完成；需要深度整理再开 `notes`/`homework`/`exam` 或 `inbox`。周末综合交付登记 `weekly`，必须读取本周实际资料和triage记录。对已表达“放好了/处理这批”的任务直接执行，不要求家长再逐项批准分拣。

## 登记、执行、续接

通用命令与字段见技能 `references/run-contract.md`，程序定义见 `references/workflow-contract.json`。

1. 用 `learning_run.py start` 扫描已确定范围，创建 `任务记录/<批次>/baseline.json` 与 `run.json`。前者保留输入、规则及更新前指纹；后者记录执行结果。
2. 紧接着运行 `learning_run.py read-rules --run <任务目录>`，实际读取并登记本批规则；没有规则读取事件不能验收或发布。
3. 每张资料记录原位置/现位置、真实类型、知识点、独立学习事件、产物去向。重复、模糊、无关各写原因；原清单不能删除。重复照片可合并学习事件，不删除原图。
4. 草稿和拟更新追踪表写 `staged/`；日常记录可以增补或依据证据修正，不能凭新学期、模型更换自动升级掌握状态。
5. 中断/换模型后读实际 `run.json`，运行 `status`，从未完成项继续；不盲目重建、重复移动或重复记一次错误。
6. 输入、规则或现有记忆发生变化时，新建修订批次，scope.request 标明承接的旧批次和变化。可复用仍适用产物，但重新核对并记录审核；不能改旧基线指纹消除报错。

规则指纹证明版本可追溯，不证明模型已理解；必须实际读取相关文件。

## 验收与正式交付

内容生成后，重新对照原始资料做审核；审核记录写对象、来源位置、发现、处理和仍有的限制。用程序的 `review` 将审核绑定实际文件，不能只填“已检查”。

- 结构检查：原资料清单齐全、处理状态与产物对应、必交付项存在且非空、索引与记忆有处理决定。
- 证据检查：诊断来源可定位、重复事件不累计、状态变化有独立作答证据。
- 题源检查：每个周重点至少关联一道与弱项匹配、逐题核验过的北京高考原题或完整节选；没有明确重点时整份周打印版也至少有一道。原题与标准答案均可回查，题图/材料与条件齐全，节选范围明确。卡片和题源限制不能替代重点真题。
- 内容检查：学科判断、公式条件、进度适配、题目与错点对应、学生练习不泄题。需要实际对照，程序无法证明学科正误。
- 周计划检查：按复盘工作流模板回看上期结果，必做任务与目标关联完整；对照家长版/总览确认完整用时、通过和停止条件及回传动作，并记录 `learning` 审核。交付完成不等于效果已验证。
- 孩子反馈检查：weekly 不预生成反馈；孩子完成本周学生版并回传后，另开 `homework + followup=true`，须有独立反馈 MD/DOCX。对照原始作答、标准答案和反馈正文核完整题目去向、对错、错点/做对处、错因确定程度、独立性、修正动作和下次通过标准。不能只更新系统记录；未知结果如实待核，具体边界见学生打印版规范。
- 版式检查：正式 DOCX/PDF 渲染后逐页检查，保留 PDF 和每页图片。不得只看第一页或看文件名宣布通过。
- 更新检查：拟更新文件有理由；原文件被其他任务更新时先合并，不覆盖新证据。

`validate` 通过后才用 `release` 将本批草稿与拟更新记忆发布到正式目录。已有文件修订使用 `--replace`，旧版留在本批 `previous/`；原始照片与输入依据不覆盖。程序校验失败则修复并重审；程序不能校验的学科判断须如实依靠对照审核，不得宣传自动保证零错误。

正式发布入口是操作约束，不是操作系统权限隔离；具备文件写权限的模型仍可能绕过。不能因此省去实际审核或把“脚本能运行”当成全系统可靠。

## 完成与限制

- 全部必交付项通过且无待核限制：可报告本批已交付。
- 模糊输入、部分题源不足或无材料学科：继续完成可靠部分，在家长说明中列出范围与限制，报告“已交付，含待核项”。不得向孩子输出待核结论。
- 所有材料都无法可靠处理或缺核心产物：报告未完成及缺口，不能用空文件通过验收。
- 结束仅需说明处理范围、正式文件、验收结果、记忆变化/维持原因、孩子下一步和必要待核项。管理细节不放孩子版。

## 规则升级与版本

技能唯一维护源由 `学了么配置.json` 的 skill_source 指定。先更新源，再安全安装并 `--check`；安装保留旧版。规则变更须更新权威文件，旧条款移入历史或明确失效，日志只记录变更，不承载另一套生效规则。

换模型保持相同工作流和验收标准。角色分工可保留，但模型名称不授予也不剥夺文件修改权限；用户已授权的日常状态维护和本次系统升级可直接执行。

测试包括完整正例和真实失败类型：漏资料/漏科、缺答案/题图、过期审核、重复照片累计、订正冒充掌握、超进度、更新冲突、中断续接。测试输出留隔离目录，不进入孩子正式资料和题库。
