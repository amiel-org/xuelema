# 学了么执行流程

本文件规定通用顺序；家庭的实际进度、题源和输出要求以资料库现行专项规范为准。任务登记与验收见 run-contract.md，必交付项来自 workflow-contract.json。

## 共用步骤

1. 读取双索引、工作区入口、执行与证据规范，以及本任务专项规范。先确认维护源与安装版本一致。
2. 明确本批范围、实际统计截止日与学科。不把整周目录名当成周日材料已上传，不把归档日期当作作答日期。
3. 由 start 扫描输入范围，紧接着用 read-rules 读取并登记本批规则。原始清单不可删除；新到资料另开批次或修订任务。大批量可分组处理，每组状态落盘，最后统一验收。
4. 生成草稿时建立原材料 → 知识点/观察 → 诊断或待验证点 → 练习 → 产物的对应关系。
5. 记忆和索引先准备拟更新文件；更新不等于必须制造新学情，没有新证据时写明维持原状的原因。
6. 对照原材料审核内容，再检查正式版式。修订了内容、题源、诊断或拟更新记忆，旧审核即失效，重新审核受影响任务。
7. 通过程序验收后发布。限制项与待核项放家长交付说明；学生版保持干净、可用。

## 临时文件

用户表达本批已准备好即开始，无需反复确认。日常常规模型只做分拣时使用 mode=triage：先逐张/逐组看原图，必要时做轻量 OCR 或视觉摘要，识别学科、资料类型、标题/章节、题号范围、页序、同组/重复关系、完整性和清晰度，并记录候选主题与下一步路由；按已核对计划 dry-run，再移动，写处理日志和分拣预索引。轻量识别只服务于路由和后续检索，不要求逐字 OCR，不判对错、不做错因或掌握诊断。原图不覆盖不删除，同名保留序号；同页重拍按同一学习事件关联。路由本身不确定或图片无法可靠读取的进入待确认，并写具体原因。triage 发布表示“识别、预索引和分拣阶段完成”，不是笔记/作业/试卷深度处理完成。

分拣后需要深度处理时再启动对应 notes、homework 或 exam；完整接入用 mode=inbox，其中每个已处理输入需关联其类型的实际产物。只把照片移动完不能算学习处理完成；但已登记的 triage 分拣阶段可以先发布并留待后续。按识别出的类型追加专项规则和必要索引/追踪更新项；若初始无法确定，先做只读识别，再登记完整 scope。

## 笔记

逐页核原图 → OCR 校对稿（保留不确定位置）→ 按知识结构整理 → 自测卡片 → 索引/知识点追踪。笔记只能支持“见到/记录过什么”，不能独自证明会做题。多页同一讲次可共用一组整理产物，但每张输入都要有去向。

## 作业

先分开印刷题干、孩子作答、订正、来源不明批注 → 核对可确认对错 → 描述观察 → 判断错因或待验证假设 → 正确做法和下一次第一步 → 索引/错因/改错追踪。不要把整页练习或有红笔的题一律标错。

## 试卷

核完整性和题号 → 逐题题干/作答/答案比对 → 保留正确、错误、未答和待核区别 → 家长诊断与学生反馈 → 少量高价值目标 → 按实际已学程度选原题/节选 → 独立验证安排 → 追踪更新。不能凭OCR空白编造总分或老师批改。

## 周复盘

本周资料深度处理时同步保留可复用的证据ID、来源位置、事件ID、知识点/错因与不确定项；需要接入五年统一目标时按[联动规范](target-linking.md)只处理增量。下一周不得为重建联动而重扫旧图；历史初始化和正式真题选题是不同出口。

先按资料库 `长期记忆/复盘工作流模板.md` 回看上期目标和实际回传，再做本周输入及知识点全集、选少量可验证目标。先查分拣/深度处理记录的实际状态，复用有效产物并回原图核关键判断；不能把 `triage` 预索引当学情结论。六科是否进入本批由 scope 明确；无材料的科目明确说明，不能默默省略，也不能凭上周推测补满。

四件套：家长周报、分科学生打印件、经过核验的练习、长期记忆更新。每个本周重点至少配一道与弱项对应、逐题核验过的北京高考原题或完整节选；卡片与校内旧题用于讲解和补充，不能替代重点真题。即使本周没有明确重点，整份周打印版也至少保留一道按本周知识点或历史待验证弱项选出的北京高考原题或完整节选。学生/答案分文件；每题能回到原题与标准答案，带必要图和完整条件。打印包存在不代表全科都必须做，必做与选做需分清。

家长版与总览先给执行摘要；`weekly_plan` 记录上期回看、完整预算、各重点关联任务、独立通过标准、停止条件与后续验证。阅读、卡片、核对及本次复测均进入预算；把正文中的所有必做与清单一起做 `learning` 审核。没有回传如实标效果待验证，不因此生成更多练习。

周打印阶段不预生成“做完后核对”。孩子完成并回传本周学生版后，按 `homework` 接入并声明 `followup=true`，以原周计划定位目标并核对原始作答，同时交付分科孩子反馈 MD/DOCX，登记知识点追踪、复盘日志与看板的更新决定。反馈标“做完后核对”，具体内容按学生打印版规范，程序字段见 run-contract.md。状态按证据规范增量更新；已有自然作业足够验证时不再加题，也不自动重出整套周报。

## 月度/学期复盘

`review` 的目标是把一段时间的学习变成孩子能看懂、能继续使用的学习地图，不是把六科各塞一道题。正式交付为一份表格化的学生月度复盘册、一份学生验证练习、一份独立答案和内部记忆更新；不生成家长版作为必交付物。完整知识点证据、文件路径和状态变更仍写入任务记录与长期记忆，学生册只展示孩子需要阅读的结论和证据摘要。

先对统计期间的全部资料做深度复盘，再建立“期间知识点覆盖表”。覆盖表至少记录科目、知识点/能力、资料事实、当前状态、做对或改善证据、典型错点、证据位置和下一次验证，包含本月各科的主要新接触、持续练习、回做内容以及截止日前最后一周的资料。若最后一周资料此前只有 `triage` 预索引，月度 `review` 必须补做逐页/逐题深度识别、必要 OCR 校对、知识点归纳、作答与批注核对、事实/解释/待验证区分，并把本次处理写入输入的 `deep_review` 记录；不能只引用分拣日志或把它标成已完成深度处理。已经在 notes/homework/exam/weekly 中完成的资料可复用，但仍须回原材料核对关键判断并记录 `reused_and_rechecked`。除确实无法可靠读取或缺核心材料的阻塞项外，不得把期间资料标为暂缓/排除；阻塞项须写具体原因、下一步和交付限制。没有独立作答证据的内容写“仅接触/待验证”，不能写成不会。把“本月覆盖”与“本月重点诊断”分开，重点只选真正需要下一步动作的少量目标。

状态沿用证据规范：一次独立做对可以支持“已改善”，不能直接写“基本掌握”；不同日期至少两次独立通过才可考虑“基本掌握”。同时保留正确表现、减量机会和仍待验证的迁移能力。错误写具体表现和确定程度，不能把“粗心”当作原因结论。

验证题按知识点和证据选择，不按学科平均分配。狭窄知识点用多个短题，多个模型联动用一道综合题；有稳定证据的科目可以只保留观察任务，没有足够证据的科目不强行凑题。每道题仍须回到核验过的原题、完整节选或有授权的改编题，并关联目标、前置证据、标准答案和学生/答案文件。原题依赖的原文、材料、图表、选项和条件必须随学生件保留；只写题意概括不算完整题面。

复盘不设固定总用时上限。题目可记录建议分钟数、分段顺序和停止条件，用于安排孩子的负担；这些数字是执行提示，不得为了满足总分钟数删掉必要的知识点覆盖。复盘册阅读、表格回看和实际答题时间分开记录，内容完整性优先于凑满或压缩某个固定时长。

学生册推荐顺序：本月学了什么 → 哪些已有表现/已改善/仍薄弱/待验证 → 典型错点与做对处 → 下月少量目标 → 验证题入口。表格和题目必须能相互定位；答案另文件保存，不能在学生册提前泄题。语文名著、文学阅读和材料题必须保留命题所给原文或完整节选，并允许多种有依据的作答，不把一个解释写成唯一答案。

## 题库与练习

新建/刷新题库才运行下载、切分和标签脚本。日常只筛与本次目标相关的候选，核最终要用的少量题。机器标签、摘要、历史“已核验”字样都不能代替当前所用原卷和答案核对。

正式原题不足时减少数量或暂缓该项，保留检索记录，继续其他可完成工作。没有明确授权不自编、不改编凑数。

## 阶段复盘与后续验证

从期间证据和实际独立作答总结趋势，不能按资料数量推断能力。先评价一次回做是否独立通过，再看不同时间的保持与迁移；改进后下调训练负担。月度/学期规则大改只在已有授权下执行，日常状态更新不以模型名称设限。
